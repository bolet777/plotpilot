## A. État actuel

### A.1 Chiffres

| Indicateur | Valeur |
|---|---|
| Code source | ≈ 6 200 lignes (`src/plotpilot`) |
| Tests | ≈ 5 000 lignes, 318 tests, ~4 s (`not hardware`) |
| État de `main` | **1 test en échec**, **1 erreur ruff** (voir B11) |
| Dépendances runtime | PySide6, svgelements, pyobjc-framework-cocoa |
| Fichiers les plus gros | `ui/main_window.py` 1 172 l., `services/plotter_service.py` 933 l., `geometry/plot_viewport.py` 412 l. |

### A.2 Architecture

Découpage en couches respecté : `ui → services → {svg, geometry, plotter, models}`.  
Aucun import Qt dans `svg/`, `geometry/`, `models/`, `plotter/`. Le protocole `PlotterBackend` + `FakePlotterBackend` permet de tout tester sans matériel.

```
fichier .svg
  → services/svg_loader.py        lecture UTF-8, ET.fromstring, SvgDocument(raw_text, root)
  → svg/layers.py                 calques Inkscape > groupes racine > document entier
  → svg/preview.py                isolation = copie racine + <defs> + deepcopy(calque)
                                  (même texte pour la preview ET le plot)
  ├─ PREVIEW  ui/preview_widget.py
  │     QSvgRenderer(texte isolé) rendu dans un rect "page mm"
  │     + overlay zone machine (services/preview_work_area.py)
  │     + ArtworkTransform (drag / X / Y / %)
  └─ PLOT     geometry/plot_viewport.py
        svgelements .segments(transformed=True) → px→mm (_SvgToMm)
        → ArtworkTransform → aplatissement 0,05 mm → Liang–Barsky (liang_barsky.py)
        → SVG "machine" (width/height/viewBox en mm, 1 <path> par polyline)
        → fichier temporaire
        → axicli file.svg -m plot -c 1 [-s -S -a -L -G1]
        → (en parallèle) axicli file.svg -v -T   → estimation de durée
```

### A.4 Ce qui est bien conçu

- Frontières UI / services / matériel strictement respectées.
- Snapshots immuables (`PlotSettings`, `MultiLayerPlotJob`, `ArtworkTransform`) ; les réglages changés pendant un plot n'affectent pas le plot en cours.
- Séquence safe-stop et machine à états de détection très bien testées (coalescence, non-chevauchement, teardown).
- Défense en profondeur : validation transform → clip géométrique → validateur de sortie → clip axicli.
- `SvgDocument.raw_text` et le fichier disque ne sont jamais modifiés.
- Suite de tests rapide, headless, sans matériel ; `qt_helpers.py` évite les sleeps.

## B. Problèmes

### B.1 Bugs confirmés empiriquement

Reproductions détaillées en [Annexe 1](#annexe-1--reproductions).

| ID | Gravité | Bug | Fichier / fonction |
|---|---|---|---|
| **B1** | Critique | **Le clipping invente des lignes.** Quand un sous-chemin sort de la zone, le point de sortie (`pen_xy`) est forcé comme départ de tous les segments suivants ; un segment extérieur→intérieur devient « point de sortie → sommet », clippé puis dessiné. Un carré partiellement hors zone produit une **diagonale inexistante**. | `geometry/plot_viewport.py` `_clip_svg_geometry.plot_segment` (l. 209–228) |
| **B2** | Critique | **Arc quasi-complet effondré en 3 points.** La longueur des arcs et quadratiques est estimée par la corde start→end ; un arc de 359° a une corde ≈ 0 → 2 pas. | `_estimate_segment_length_rendered` (l. 300–317) |
| **B3** | Critique | **Unités sans `viewBox` : heuristique instable.** Un fichier `width="297mm"` sans viewBox voit ses coordonnées traitées en **mm** si elles sont petites, en **px** si un élément dépasse la page. Le même dessin change d'échelle (×3,78) selon le contenu. Le standard SVG, axicli et Inkscape disent toujours px. | `_coordinates_are_viewport_pixels`, `_read_viewbox_user` |
| **B4** | Critique | **Preview ≠ plot sur fichiers sans viewBox.** Qt convertit `mm` à **90 dpi** (297 mm → 1052 px), svgelements à 96 dpi. Preview 6,7 % plus petite que le plot dans le « bon » cas, ×3,5 dans le mauvais. | `ui/preview_widget.py` `_paint_physical_preview` |
| **B5** | Critique | **L'isolation d'un calque change l'échelle (documents px).** `ET.tostring` produit `<ns0:svg …>` ; la regex `<svg[^>]+width` ne matche plus → fallback sur `width_mm`. Rect de 100 px : **100 mm** isolé vs **26,46 mm** document entier. | `svg/preview.py` (pas de `register_namespace`), `_read_viewbox_user` |
| **B6** | Haute | **`<style>` racine perdu à l'isolation** (exports Illustrator, Figma, vpype avec classes CSS). Les formes perdent leur stroke → filtrées → « No artwork intersects the plot area » ; la preview affiche des aplats noirs. | `svg/preview.py` `_append_defs` |
| **B7** | Haute | **Sous-calques Inkscape** : listés comme calques indépendants (contenu dupliqué avec le parent) ; isolés, ils perdent `transform` et styles hérités → mauvaise position ou rien. | `svg/layers.py` `_extract_inkscape_layers` (`root.iter()`), `svg/preview.py` |
| **B8** | Haute | **Formes fill-only ignorées silencieusement** ; la preview les montre ; axicli en tracerait le contour. | `_element_has_stroke` |
| **B9** | Moyenne | **`preserveAspectRatio`** : la preview étire (`QSvgRenderer` = IgnoreAspectRatio), le plot respecte `xMidYMid meet`. | `preview_widget.py` |
| **B10** | Moyenne | **Regex `viewBox` globale** : prend le premier `viewBox=` du texte (marker, symbol, pattern, svg imbriqué). | `_VIEWBOX_RE` |
| **B11** | Haute (hygiène) | **`main` n'est pas vert** : `tests/test_main_window_multi_layer.py::test_synthetic_document_layer` échoue (la préparation est devenue asynchrone, l'erreur n'est plus un modal) ; `tests/test_square_pipeline_regression.py` : ruff I001 + format. | tests |
| **B12** | Haute | **Auto-rotate axicli implicite.** Sans `-N`, axicli tourne de 90° toute page portrait. Avec « Default (CLI) » + fallback A4/A3 (portrait), la sortie 210×297 est tournée sur la machine sans que la preview l'indique. Le message « automatic rotation is not implemented » est faux. | `models/plot_settings.py`, `services/bounds_service.py` |
| **B13** | Basse | Points dégénérés émis (`M 10 10 L 10 10 L 20 10`, `line` de longueur nulle). Inoffensif, bruit. | `_clip_svg_geometry` |

### B.2 Dette technique, fragilité, couplage

| ID | Constat | Fichiers |
|---|---|---|
| **D1** | **Deux moteurs de rendu concurrents** : Qt pour la preview, svgelements pour le plot. Rien ne garantit structurellement PREVIEW = OUTPUT ; cause racine de B4, B8, B9 et des divergences texte / dashes / markers / images / clip-path. | `ui/preview_widget.py`, `geometry/plot_viewport.py` |
| **D2** | `ui/main_window.py` (1 172 l.) est un god-object : 9 labels d'état empilés, projet, transform, bounds, multi-calques, menus. | `ui/main_window.py` |
| **D3** | `services/plotter_service.py` (933 l.) : détection + plot + safe-stop + progression + estimation dans une classe, ~10 flags booléens (`_pending_refresh`, `_pending_presence_after_resume`, `_auto_detect_paused`, …). Bien testée mais coûteuse à faire évoluer. | `services/plotter_service.py` |
| **D4** | Parsing géométrique par **regex sur texte** (`_read_viewbox_user`, `<svg[^>]+width`) alors que l'arbre ET est disponible. | `geometry/plot_viewport.py` |
| **D5** | `_is_under_defs` refait un `_element_path` (parcours complet) pour **chaque** drawable → **O(n²)** à l'ouverture. Un SVG génératif de 50 k paths sera lent. | `svg/layers.py` |
| **D6** | `bounds_service` quasi informatif depuis 015, mais messages contradictoires (« Artwork exceeds selected model » alors que le plot continue). | `services/bounds_service.py` |
| **D7** | Concept « Default (CLI) » + `FallbackWorkArea` + `hardware_verified` : complexité (settings, projet v1, UI, tests) pour un cas incompréhensible par l'utilisateur. | `preview_work_area.py`, `settings_service.py`, `project_file_service.py`, UI |
| **D8** | Duplication : `_local_tag` ×3, `_fmt_mm` ×2 ; `plot_service.py` et `preview_service.py` sont des pass-through identiques vers `build_layer_preview_svg`. | `svg/`, `services/` |
| **D9** | `-G` omis quand l'optimisation est décochée → axicli prend la valeur de **sa** config utilisateur : comportement non déterministe d'une machine à l'autre. | `models/plot_settings.py` |
| **D10** | Docs en retard : README « slices 001–010 », `specs/README.md` sans 011/012/016, `ARCHITECTURE.md` sans `geometry/`. | `README.md`, `specs/README.md`, `docs/ARCHITECTURE.md` |
| **D11** | `plotpilot.spec` sans `hiddenimports` pour `PySide6.QtSvg` / `svgelements` (fonctionne par analyse, fragile). | `packaging/macos/plotpilot.spec` |
| **D12** | `_extract_inkscape_layers` utilise `root.iter()` : un calque déclaré dans `<defs>` serait listé. | `svg/layers.py` |

## C. UX

Point de vue : un utilisateur qui veut ouvrir → voir → choisir les calques → placer → couper → optimiser → régler → lancer → changer de stylo.

| ID | Problème | Impact |
|---|---|---|
| **U1** | **Deux notions de sélection** : « Plot Selected Layer » (ligne surlignée) vs « Plot Checked Layers » (cases). | Confusion ; risque de tracer le mauvais calque. |
| **U2** | **Jargon technique exposé** : « Model: Default (CLI) », « Work area A4/A3 (not verified hardware) », « axicli enforces limits », `-G1`. | L'utilisateur doit comprendre axicli. |
| **U3** | **Pas de notion de feuille** : seule la zone de course machine est dessinée ; pas de format papier, marges, origine ; pas de Fit-to-page / Center / Rotation 90° ; échelle en % sans dimension cible en mm. | Placement laborieux, imprécis. |
| **U4** | **Layout** : réglages toujours déployés ; ~9 labels d'état empilés ; erreurs tantôt en modal, tantôt dans un label bas de fenêtre. | Charge visuelle, messages ratés. |
| **U5** | **Preview non fiable pour décider** : texte, aplats, dashes, images apparaissent mais ne seront pas tracés ; aucun compteur d'éléments ignorés ; message « No artwork intersects the plot area » pour un calque caché ou fill-only. | Perte de confiance, papier gâché. |
| **U6** | **Réglages AxiDraw essentiels absents** : hauteur stylo haut/bas (`-u/-d`), vitesse constante (`-C`) ; pas de boutons Home / Désactiver moteurs (pourtant dans le backend) ; pas de Pause/Reprise (`res_plot`). | Passage obligé par le terminal ou Inkscape. |
| **U7** | Changement de stylo : simple label + « Continue » ; pas de mise en avant (modal, couleur en grand, nom du calque suivant). | Erreur de stylo. |
| **U8** | Pas de glisser-déposer de SVG, pas de fichiers récents. | Friction. |
| **U9** | Estimation seulement **après** lancement ; aucune comparaison avec/sans optimisation. | Pas d'aide à la décision. |
| **U10** | Drag de l'artwork sans feedback (curseur, flèches clavier, snap). | Imprécision. |
| **U11** | Calques `display:none` listés comme les autres, sans indicateur. | Incompréhension. |

## D. Pipeline SVG → AxiDraw

Objectif : **ce qui apparaît dans la preview doit correspondre à ce que l'AxiDraw trace**.

| Étape | Risque | Statut | Réf. |
|---|---|---|---|
| Parsing | Regex sur texte pour viewBox/width ; préfixe `ns0:` après isolation | **Confirmé** | B5, B10, D4 |
| Unités | Sans viewBox : heuristique mm/px instable ; Qt 90 dpi vs svgelements 96 dpi | **Confirmé** | B3, B4 |
| viewBox | Origine non nulle + `rotate(-90)` (`CarreA4.svg`) | ✅ Correct (bbox 5,14–291,86 × 3,23–206,77 mm) | — |
| preserveAspectRatio | Plot correct, preview étirée | **Confirmé** | B9 |
| Transforms imbriquées | svgelements `transformed=True` correct ; ancêtres perdus à l'isolation des sous-calques | **Confirmé** | B7 |
| Groupes / calques | Sous-calques dupliqués ; `<style>` perdu ; calques cachés listés | **Confirmé** | B6, B7, U11 |
| Primitives | rect / circle / ellipse / line / polyline / polygon / `<use>` OK ; `text` ignoré (cohérent avec axicli, pas avec la preview) | ✅ / à signaler | U5 |
| Aplatissement | Arcs quasi-fermés effondrés ; corde sous-estime arcs et quadratiques ; cap 512 pas (OK jusqu'à ~140 mm de rayon, erreur 0,0007 mm) | **Confirmé** | B2 |
| Clipping | Lignes parasites à la sortie/rentrée de zone | **Confirmé — le plus grave** | B1 |
| Filtrage | fill-only supprimé, contrairement à axicli | **Confirmé** | B8 |
| Sortie → axicli | SVG mm/mm propre ; auto-rotate implicite pour pages portrait ; `-G` absent = config machine | Risque | B12, D9 |
| Coordonnées Qt ↔ mm | `PhysicalPreviewLayout` cohérent, drag testé | ✅ | — |
| Multi-calques | Même `ArtworkTransform` et réglages snapshotés pour toutes les couches | ✅ | — |

## G. Roadmap

Huit étapes, chacune livrable et testable indépendamment (une PR par étape, avec sa tranche de golden tests).

- [ ] **Étape 1 — Baseline & golden suite** (aucun changement de comportement)  
  Réparer B11 et ruff ; mettre à jour les docs (D10) ; créer `tests/fixtures/golden/` (Annexe 2) avec polylignes attendues en mm ; marquer les cas cassés `xfail` avec la référence du constat.  
  *Sortie : `main` vert, bugs documentés par des tests.*

- [ ] **Étape 2 — Correctifs géométriques P0 dans le moteur actuel**  
  B1 (continuité clipping), B2 (arcs), B13 (points dégénérés). Les `xfail` correspondants passent.  
  *Sortie : plus de lignes parasites, cercles complets.*

- [ ] **Étape 3 — Canonicalisation unités / viewBox**  
  `SvgPageGeometry` unique depuis l'arbre ET ; suppression regex et heuristique (B3, B5, B10, D4) ; `register_namespace` ; même résultat document entier vs calque isolé. Décision explicite : sans viewBox, user unit = px (standard).

## Annexe 1 — Reproductions

Toutes les sondes appellent `prepare_positioned_plot_svg(svg, viewport_width_mm, viewport_height_mm, transform=identity)` et lisent la bbox / les polylignes du SVG produit. Chaque cas est directement convertible en test golden.

### B1 — Clipping : diagonale parasite

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="200mm" height="200mm" viewBox="0 0 200 200">
  <path d="M 50 50 L 150 50 L 150 150 L 50 150 Z" fill="none" stroke="black"/>
</svg>
```
Viewport 100 × 100 mm.  
**Obtenu** : une polyline `(50,50) → (100,50) → (75,100) → (50,50)`.  
**Attendu** : `(50,50) → (100,50)` et `(50,100) → (50,50)`.  
Identique avec `<rect x="50" y="50" width="100" height="100"/>` et avec `ArtworkTransform(scale=2)` sur le carré 10–90 (obtenu `(20,20)→(100,20)→(60,100)→(20,20)`).

### B2 — Arc quasi-complet

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="100mm" height="100mm" viewBox="0 0 100 100">
  <path d="M 70 50 A 20 20 0 1 1 69.999 50.02" fill="none" stroke="black"/>
</svg>
```
**Obtenu** : 3 points, bbox (70, 50, 100, 51,5).  
**Attendu** : cercle r = 20, bbox ≈ (30, 30, 70, 70), plusieurs dizaines de points.  
Contrôle : demi-cercle r = 140 → 513 points, erreur de flèche 0,0007 mm (OK).

### B3 — Unités sans viewBox, heuristique instable

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="297mm" height="210mm">
  <rect x="10" y="10" width="100" height="50" fill="none" stroke="black"/>
</svg>
```
**Obtenu** : bbox (10, 10, 110, 60) mm — coordonnées prises pour des mm.  
**Attendu (SVG / axicli / Inkscape)** : 1 user unit = 1 px = 25,4/96 mm → bbox (2,65, 2,65, 29,1, 15,9).  
En ajoutant `<line x1="0" y1="0" x2="1100" y2="0"/>` au même fichier, le rect passe à (2,65, 2,65, 29,1, 15,9) : **l'échelle dépend du contenu**.

### B4 — Qt à 90 dpi

`QSvgRenderer.viewBoxF()` sur le fichier B3 = (0, 0, 1052,36, 744,09) → 297 mm = 1052 px (90 dpi). svgelements : 1122,5 px (96 dpi). La preview rend ce viewBox dans un rect de 297 × 210 mm : le rect 10–110 apparaît à 2,8–31 mm alors que le plot le trace à 10–110 mm.

### B5 — Isolation et préfixe `ns0:`

Document px avec un calque Inkscape :
```svg
<svg xmlns="http://www.w3.org/2000/svg" xmlns:inkscape="http://www.inkscape.org/namespaces/inkscape" width="800" height="600">
  <g inkscape:groupmode="layer" inkscape:label="L">
    <rect x="0" y="0" width="100" height="100" fill="none" stroke="black"/>
  </g>
</svg>
```
Texte isolé commence par `<ns0:svg xmlns:ns0="http://www.w3.org/2000/svg" …>` ; `re.search(r"<svg[^>]+width…")` → `None`.  
**Document entier** : bbox (0, 0, 26,46, 26,46) mm ✅. **Calque isolé** : bbox (0, 0, 100, 100) mm ✗.

### B6 — `<style>` racine perdu

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="100mm" height="100mm" viewBox="0 0 100 100">
  <style type="text/css">.st0{fill:none;stroke:#000000;}</style>
  <g id="Layer_1"><rect class="st0" x="10" y="10" width="50" height="50"/></g>
  <g id="Layer_2"><rect class="st0" x="60" y="60" width="20" height="20"/></g>
</svg>
```
Calques détectés : « Layer 1 », « Layer 2 », couleur `None`. `<style>` absent du texte isolé.  
**Document entier** : 2 paths, bbox (10, 10, 80, 80) ✅. **Calque isolé** : `PlotViewportError: No artwork intersects the plot area.` ✗

### B7 — Sous-calque dans un parent transformé

```svg
<svg … width="100mm" height="100mm" viewBox="0 0 100 100">
  <g inkscape:groupmode="layer" inkscape:label="Parent" transform="translate(40,40)" stroke="black" fill="none">
    <g inkscape:groupmode="layer" inkscape:label="Child">
      <rect x="0" y="0" width="10" height="10"/>
    </g>
  </g>
</svg>
```
Calques listés : Parent (1 drawable), Child (1 drawable) — **le même rect compté deux fois**.  
Parent isolé : bbox (40, 40, 50, 50) ✅. Child isolé : erreur « No artwork intersects » (stroke hérité perdu ; avec un stroke propre il serait tracé à (0, 0) au lieu de (40, 40)).

### B8 — Fill-only

```svg
<svg … width="100mm" height="100mm" viewBox="0 0 100 100">
  <rect x="10" y="10" width="50" height="50" fill="#336699"/>
</svg>
```
Preview : carré bleu plein. Plot : `No artwork intersects the plot area.` axicli tracerait le contour.

### B9 — preserveAspectRatio

```svg
<svg … width="200mm" height="100mm" viewBox="0 0 100 100">
  <rect x="0" y="0" width="100" height="100" fill="none" stroke="black"/>
</svg>
```
Plot : bbox (50, 0, 150, 100) — carré centré, conforme `xMidYMid meet` ✅. Preview : Qt étire le viewBox 100 × 100 dans 200 × 100 mm → rectangle ✗.

### B10 — Regex viewBox

```svg
<svg … width="100mm" height="100mm">
  <defs><marker id="m" viewBox="0 0 10 10"/></defs>
  <rect x="10" y="10" width="50" height="50" fill="none" stroke="black"/>
</svg>
```
`_read_viewbox_user` retourne (0, 0, 10, 10) — le viewBox du marker. Résultat correct ici par coïncidence (bascule px), mais fragile.

### Cas validés (à conserver comme non-régression)

- `CarreA4.svg` (viewBox `-500 -105 1052.36 744.09`, rect `rotate(-90)`) → bbox (5,14, 3,23, 291,86, 206,77) mm ✅
- Circle, `<use>`, stroke hérité via `style` de groupe, sous-chemins multiples et commandes relatives ✅
- `display:none` : svgelements et Qt ignorent tous deux l'élément (cohérent, mais message d'erreur trompeur, U11)
