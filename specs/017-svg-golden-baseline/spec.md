# Feature Specification: SVG golden baseline

**Feature Branch**: `017-svg-golden-baseline`  
**Created**: 2026-09-30  
**Status**: In review  
**Input**: Reliability roadmap step 1 from `docs/AUDIT-2026-09-30.md`. Restore a green test baseline and encode confirmed SVG geometry bugs as oracles. Do not fix those bugs in this slice.

## User Scenarios & Testing

### User Story 1 - Green baseline (Priority: P1)

A developer can run the fast suite and ruff and see no unexpected failures. The previous red `main` (B11, ruff I001) is fixed in tests only.

**Independent Test**: `./scripts/test_fast.sh` exits 0. `uv run ruff check src tests` exits 0.

### User Story 2 - Known-good geometry stays locked (Priority: P1)

Squares, the CarreA4-style transformed page, a translate, and relative multi-subpath paths keep the millimeters already verified by the audit.

**Independent Test**: Passing cases in `tests/test_golden_svg.py`.

### User Story 3 - Confirmed bugs are visible oracles (Priority: P1)

B1, B2, B3, B5, B6, B7, and B10 fail against the correct millimeters and are marked `xfail` with the audit id. Expected JSON describes the correct result, not today's output.

**Independent Test**: Those tests are XFAIL, not FAIL. After a later fix they become XPASS.

### User Story 4 - Undecided fill-only policy is not chosen (Priority: P2)

B8 / Q1 stays a recorded fixture. The suite does not assert whether fill-only shapes are plotted.

## Edge Cases

- Near-complete arc `A 20 20 0 1 1` (B2). The audit's approximate box (30..70, 30..70) matches sweep-flag 0. The path uses sweep-flag 1, so the oracle uses the SVG center near (89.97, 51.01), clipped at the 100 mm viewport.
- Marker `viewBox="0 0 10 10"` (B10) currently matches CSS px by coincidence. That output is a passing lock. `viewBox="0 0 200 200"` changes the scale and is the xfail.
- T7 must not keep treating the B3 large-coordinate heuristic as the specification.

## Requirements

### Functional Requirements

- **FR-001**: No change to production clipping, arc flattening, unit heuristic, preview DPI, namespace serialization, style isolation, nested layers, fill-only filtering, `preserveAspectRatio`, or root viewBox parsing.
- **FR-002**: `tests/test_main_window_multi_layer.py::test_synthetic_document_layer` waits for `PlotPhase.FAILED` and multi-layer `ERROR` (B11).
- **FR-003**: Golden fixtures live under `tests/fixtures/golden/<category>/` as `<case>.svg` plus `<case>.expected.json` in millimeters.
- **FR-004**: Expected values are hand-calculated. They are not generated by `prepare_positioned_plot_svg`.
- **FR-005**: The test oracle parses prepared `M`/`L` output. It does not call the clipper or flattener.
- **FR-006**: Default comparison tolerance is 0.02 mm.
- **FR-007**: XFAIL reasons include the audit id (`B1`, `B2`, `B3`, `B5`, `B6`, `B7`, `B10`).
- **FR-008**: B8 records `policy: pending` and does not assert plot geometry (Q1).
- **FR-009**: Docs that still say slices stop at 010 are updated through 016, and `geometry/` is named in the architecture map (D10).

## Success Criteria

- Fast suite and `pytest -m "not hardware"` finish in under 15 seconds with 0 failed tests.
- XFAIL tests are expected. XPASS is reported, not treated as a silent pass.
- Ruff check and format check are clean.
- No hardware tests and no physical plot.

## Assumptions

- Pattern-generator work stays behind this reliability slice.
- Later slices remove `xfail` marks when the corresponding bug is fixed. They do not rewrite the expected millimeters to match broken output.
